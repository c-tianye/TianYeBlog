## 版本概览

Pi 1.6.0 是一次重要更新，主要推出了针对 OpenAI、Azure 及 OpenAI-Codex Provider 的 GPT-6.2 Astra 与 GPT-6.2 Sol 模型支持，并将 GPT-6.2 Sol 设为默认模型。此外，本次更新还调整了扩展组件的 API 渲染机制，更新了 Qwen 令牌计划提供商配置，并包含了多项安全修复与工具行为优化。

## 逐版本解读

### Pi 1.6.0（2026-11-20）

**新增**

- 针对 openai、azure 和 openai-codex 提供商新增 GPT-6.2 Astra 与 GPT-6.2 Sol 模型支持，其中 GPT-6.2 Sol 成为三者的默认模型（详见 [Providers](https://docs.pi.dev/latest/providers)）。两款模型均不支持思维等级关闭选项；Azure 提供 1.05M 上下文窗口，Codex 为 GPT-6.2 Sol 提供 500K、为 Astra 提供 272K 上下文。
- 为 Qwen Token Plan Individual 提供商新增 `qwen4-max-preview`（[#12259](https://github.com/earendil-works/pi/issues/12259)）。
- 新增 `deepseek-v4.1-flash` 与 `deepseek-v4.1-flash-1017` 模型接入，并支持针对不同 Plan 的专属环境变量如 `QWEN_TOKEN_PLAN_TEAM_API_KEY` 等（[#11773](https://github.com/earendil-works/pi/issues/11773)）。
- 当 OpenAI 在 GPT-6.2 上压缩上下文并丢弃推理项时，在转录中显示提示通知。

**改动**

- Qwen Token Plan 提供商更新了网关地址并更名为 "Qwen Token Plan Team" 和 "Qwen Token Plan Team CN"（[#11773](https://github.com/earendil-works/pi/issues/11773)）。
- 更新 `undici` 依赖至 8.12.4 版本以修复多项安全漏洞（[#12200](https://github.com/earendil-works/pi/issues/12200)）。
- openai、azure 和 openai-codex 提供商的默认模型更新为 `gpt-6.2-sol`（与 GPT-6.1 Sol 价格相同）。
- `find` 工具的路径匹配模式调整为相对于搜索目录（[#12066](https://github.com/earendil-works/pi/issues/12066)）。
- `llama.cpp` 扩展默认连接端口变更为 9931（[#12001](https://github.com/earendil-works/pi/pull/12001) 由 [@julien-c](https://github.com/julien-c) 贡献）。
- 基址为 `api.anthropic.com` 的提供商默认开启 Anthropic 消息线程（[#11987](https://github.com/earendil-works/pi/issues/11987)）。
- 退出时打印的恢复会话命令单独置于新行，便于三击选中（[#12237](https://github.com/earendil-works/pi/issues/12237)）。

**修复**

- 修复了 `read` 命令记录当前模型不支持图像的提示信息会在切换到视觉模型后被重复作为陈旧文本发送给模型的问题（[#12131](https://github.com/earendil-works/pi/issues/12131)）。

**破坏性变更**

- 扩展组件变更：`render()` 现在返回 `readonly string[]`，`Container` 在子组件未改变时返回相同的缓存数组。原地修改 render 输出的扩展（包括在 Container 子类中调用 `super.render()`）必须先对输出进行拷贝（[#9549](https://github.com/earendil-works/pi/issues/9549)）。

## 升级建议

建议所有用户升级至 Pi 1.6.0 以体验全新的 GPT-6.2 模型与安全更新。如果是扩展插件开发者，升级前请务必检查并调整 `render()` 方法中对只读数组的操作逻辑。
