## 版本概览

本期包含 Pi 1.2.0 版本的正式发布。该版本带来了针对 OpenRouter 的按 Key 模型过滤、官方配置 Schema 支持、远程会话 OSC 52 剪贴板同步等特性，并重构了插件的运行启动事件与会话忙碌状态处理逻辑。

## 逐版本解读

### Pi 1.2.0（2026-10-12）

**新增** —— 覆盖 New Features 与 Added

- 支持针对特定 OpenRouter Key 的模型列表过滤：仅展示该 Key 有权调用的模型，并同步其上下文长度、最大输出 token 及价格，支持 models.json 中配置的区域端点，列表支持离线缓存（[文档](https://pi.dev/docs/latest/providers#openrouter)）。
- 发布官方配置 Schema：可在 settings.json、models.json、keybindings 与 themes 中添加 $schema 实现编辑器校验与补全（参考 [Settings](https://pi.dev/docs/latest/settings)、[Models](https://pi.dev/docs/latest/models)、[Keybindings](https://pi.dev/docs/latest/keybindings)、[Themes](https://pi.dev/docs/latest/themes)）。
- 远程会话剪贴板支持：新增环境变量 PI_CLIPBOARD_OSC52=1，以便在 Pi 无法自动检测远程会话时（例如通过多路复用器连接），将复制内容传送到远程客户端剪贴板（[文档](https://pi.dev/docs/latest/environment-variables#pi-process-configuration)）。
- Codemode 优化：工具声明支持展示输入约束（如 integer、最小值/最大值及默认值），Codemode 界面行显示耗时与总执行时间（[文档](https://pi.dev/docs/latest/codemode)）。
- 扩展触发运行支持 before_agent_start：通过 pi.sendMessage(..., { triggerTurn: true }) 触发的运行与常规提示词经历相同的初始化流程（[文档](https://pi.dev/docs/latest/extensions#events-and-concurrency)）。
- 工具定义新增 reachesTools 属性：供具有工具转发特性的工具（如 codemode 和 tool_search）声明可能调用的下游工具，以便 MCP 扩展提前等待对应服务器就绪。
- 工具命名空间增加别名支持：codemode 的 describeNamespace() 与 searchTools() 的 namespace 选项均支持别名匹配，MCP 命名空间采用服务器名称。

**改动** —— 覆盖 Changed

- 变更了 pi mcp list --json 的输出格式：对于提供资源的服务器直接报告 resources: true，不再输出具体的 resources 和 resourceTemplates 计数；连接时 Pi 不再主动枚举资源（[#10526](https://github.com/earendil-works/pi/issues/10526)）。

**修复** —— 覆盖 Fixed，保留 PR/issue 链接

- 修复了模型列表拉取与离线缓存相关问题（[#10353](https://github.com/earendil-works/pi/issues/10353)）。
- 修复了运行状态重入与取消中断异常处理（[#10739](https://github.com/earendil-works/pi/pull/10739)）。

**破坏性变更** —— 仅当输入里有 Breaking Changes 时输出这一节，并说明升级时需要改什么

- 主题 Schema 地址变更与严格校验：生成的配置 Schema 统一发布至 https://pi.dev/schemas/*.schema.json，主题 Schema 迁移至 https://pi.dev/schemas/theme.schema.json。启动时加载的主题现在会执行相同的 Schema 校验。升级时需要更新主题中的 $schema 引用，在 vars 下定义复用颜色，并清理不支持的元数据字段（[#9880](https://github.com/earendil-works/pi/pull/9880)，[#10751](https://github.com/earendil-works/pi/pull/10751)）。
- before_agent_start 事件类型变更：idle 状态下由 pi.sendMessage(..., { triggerTurn: true }) 触发的运行现在也会触发 before_agent_start。BeforeAgentStartEvent 调整为基于 messageType 的联合类型（"user" 类型包含 prompt 和 images，"custom" 类型包含起始 message 且无 prompt）（[#10267](https://github.com/earendil-works/pi/issues/10267)，[#5581](https://github.com/earendil-works/pi/issues/5581)，[#10739](https://github.com/earendil-works/pi/pull/10739)）。
- 运行启动期间会话状态判定为忙碌：在运行启动期间（包含 before_agent_start 执行期间），ctx.isIdle() 为 false；pi.sendMessage() 将进入排队而非因并发抛出 "Agent is already processing"；pi.sendUserMessage() 必须指定 deliverAs；在此期间发起的 abort 将在运行启动完成后立即执行取消（[#10739](https://github.com/earendil-works/pi/pull/10739)）。
- pi mcp list --json 格式变更：不再输出资源数量统计，调用脚本需按 resources: boolean 处理（[#10526](https://github.com/earendil-works/pi/issues/10526)）。

## 升级建议

建议升级至 1.2.0。如果使用了自定义主题或编写了 Pi 扩展插件，升级前请注意适配 $schema 路径与 before_agent_start 事件的类型联合变化。
